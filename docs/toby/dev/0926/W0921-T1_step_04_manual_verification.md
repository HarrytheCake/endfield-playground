# 步驟 04：手動驗收

## 目標

在 `pnpm dev` 首頁確認真機器點擊落子的可見行為，並核對空值、重複操作與既有資料。

## 驗收案例

| 操作                                          | 預期                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------- |
| 開首頁                                        | 顯示既有 `connected` mock，不因接線消失；初始快照進 history 的限制維持原狀 |
| 未選真機器時點空格                            | 無新增設備                                                                 |
| 選「基礎生產」真機器後點空格                  | 新設備出現；中文名及佔格符合機器資料                                       |
| 保持武裝連點三處合法空格                      | 三台新設備均出現                                                           |
| 點已有設備或管線佔格                          | A0 預檢拒絕；無新增，history 不增加                                        |
| 點格線、文字附近與畫布外 padding              | 落點以 SVG 格座標為準，padding 不落子                                      |
| 選未知／失效的機器 id 或遇到 `addDevice` 失敗 | 不建立錯誤設備；不誤報為成功                                               |
| 同機再點、切分類、點舊按鈕                    | 本地高亮及新落子意圖同步解除                                               |
| 按 Esc                                        | 維持既有快捷鍵設定行為；新意圖不因 Esc 自動解除                            |

使用者授權在本分支自建預檢後執行驗收。記錄畫布尺寸與選用機器，避免因預設 12×8 格及 mock 佔格把合法落點誤判為程式失敗。檢查新增設備的 Undo；勿把 mock 快照的 Undo 過渡限制列為本工單缺陷。

## 驗收條件

- 必要案例實際跑過並有結果；失敗案例保留重現步驟。
- 不以 Storybook 靜態展示取代首頁互動驗收。

## 執行結果（2026-09-26）

使用 Chrome 無頭模式打開 `pnpm dev` 首頁，以瀏覽器點擊事件驗證：原有 2 個 mock 設備仍顯示；從「基礎生產」選「塑型機」後，空格新增設備並顯示中文名，新增佔格為資料列所示 3×3；再次點相同格不新增；另點兩處空格，合計連放三台；同機再點、切分類或點舊按鈕後不再按新意圖落子。SVG 子元素上的點擊仍以 SVG 座標換算；點外側 padding 或 SVG 邊界外不落子。臨時驗證腳本已移除。未知機型、非有限座標與管線重疊由純函式測試驗證，新增操作的 history 行為由既有 store 測試覆蓋。這次以瀏覽器派發事件驗證資料流，尚未做實體滑鼠、Esc 視覺流程或鍵盤無障礙測試。
