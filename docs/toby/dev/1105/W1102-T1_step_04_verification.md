## 目標與檔案

## 驗收案例

| 案例 | 操作／資料 | 預期 |
| --- | --- | --- |
| 無設備 | 正式 layout 設備為空 | 顯示「尚未擺放設備」，無殘留品項 |
| 有設備無摘要 | 放置未構成有效產線的設備 | 不顯示「尚未擺放設備」；不假造數字 |
| 基準產線 | 源礦 30/min → 粉碎機 → 輸入口，兩段有效 belt | 源礦、源石粉末產出與消耗各 30/min，淨值約 0 |
| 中間物 | 檢查上述列表 | 不因淨值為零隱藏源礦或源石粉末 |
| 連線變更 | 用目前支援的畫布操作建立／改變有效連線 | 計算排程後數字對應新拓撲，不保留舊結果 |
| 清空結果 | 透過既有可用入口載入空 layout；記明操作方法 | 計算後 summary 清空，回到無設備文案 |
| 多筆與極端值 | Story 注入負淨值、小數、長名、多筆資料 | 符號、精度、單位與捲動正常 |
| 供水已知問題 | 對照未完成的水源型態 | 若媒質不符，列上游問題，不改 harry 範圍 |
| 面板開合 | 收合再展開並變更產線 | 資料仍更新，不新增計算監聽 |

## 執行與限制

1. 先跑直接相關整合測試，再開正式頁及 Story 人工核對。
2. D1 的 150ms 是現有 debounce 設定；觀察並記錄端到端更新時間，不將它誤稱為硬性完成上限。
3. 同一組資料若在純函式正常、正式頁失敗，優先查 L2 轉接、machineType、handle、primaryOutput 與媒質。
4. 不新增 Delete／旋轉功能來完成驗收；不修改凍結檔案繞過上游問題。
5. 不主動產生截圖或 JSON 報告；以文字／Markdown 記錄指令、預期、實際結果。
6. 修改過的 Story 檢查 Controls、邊界狀態與 Accessibility；列明未能驗證項目。

驗收條件：本週核心案例均有實際證據；純函式測試、mock Story 與正式頁結果分開記錄。
