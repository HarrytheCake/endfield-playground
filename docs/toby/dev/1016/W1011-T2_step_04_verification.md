# W1011-T2 步驟 04：操作與回歸驗收

狀態：已完成自動瀏覽器操作驗收（2026-10-16）；案例與實際證據如下，實體裝置及完整無障礙人工流程未執行。

## 目標與檔案

以正式首頁為主要操作入口，驗證真實事件流程；必要修正僅限前兩步允許檔案。不得為驗收改動 MainLayout、store 或加永久測試 UI。

## 驗收矩陣

| 案例 | 操作 | 預期 |
| --- | --- | --- |
| 合法移位 | 拖設備至空位放開 | 拿起預覽跟隨，放開移位，單筆歷史 |
| 重疊拒絕 | 拖至另一台設備佔格 | 放開回原位、不彈窗、無新增歷史 |
| 管線衝突 | 拖至 L1 判定衝突的管線格 | 完全依 action 拒絕結果，不在 L2 加規則 |
| 抓取偏移 | 從多格設備中心／邊角拿起 | 保持抓取相對位置，無跳位 |
| 旋轉設備 | 對 90／270 度設備不同格按下 | 命中與可見佔格一致，不修改 rotation |
| 點設備 | 按下放開且不超過門檻 | emit 該實例 ID，不新增／移動設備 |
| 點空白 | 未武裝時點空白 | emit null，不移動畫布 |
| 武裝落子 | 選機器後點空白，再連續點擊 | 保留原預檢與連續落子，每次只新增一台 |
| 武裝下移動 | 已武裝時拖既有設備 | 只移位，尾隨 click 不新增設備 |
| 空白平移 | 選取工具下拖空白 | 只改視角，不落子、不誤拖設備 |
| 原有平移 | 中鍵、頂欄平移工具、既有 Space 平移 | 包含從設備上開始，均維持視角平移 |
| 取消 | 拖設備後觸發 pointercancel | 回原位、無提交／選取／落子 |
| 失去捕捉 | 拖設備後失去 pointer capture | 清狀態、不提交；下一次操作正常 |
| 卸載 | 手勢中卸載元件 | 不提交，不留 capture 或監聽副作用 |
| 多指標／右鍵 | 拖曳中加入另一 pointer，或右鍵按下 | 不搶走手勢、不造成第二筆提交 |
| 拖回原格 | 超過門檻後回原格放開 | 不新增移動歷史，不當單純點選 |
| 最後座標 | 放開點不同最後一次 move | 以放開點決定最終格 |
| 平移與縮放換算 | 不同 offset／zoom 下拖曳 | 顯示與落格一致；不為此新增縮放 UI |
| 非零 z | 使用既有測試資料驗證 | 拖曳保留設備 z，不強制歸零 |
| 空值與失效資料 | 空設備、未知預覽 ID、拖曳中設備消失 | 無例外、無假設備，狀態可清理 |
| 基地出界 | 拖至基地框外空位 | 依既有 action 結果；成功時 Error 顯示延續，不新增邊界拒絕 |
| 管線留原位 | 移動原本相連設備 | 管線座標不變，允許衍生連線斷開 |
| 拿起視覺 | 亮／暗模式查看拖曳設備 | 可辨識淺藍拿起狀態，不只灰色透明 |

## 驗證方式與證據

1. 執行 pnpm dev，確認首頁仍掛 LayoutView。記錄環境、基準與實際測試入口。
2. 以可用瀏覽器／事件測試工具觀察事件、action 次數與 history 深度；不得只看最後位置推論沒有中途寫 store。
3. 首頁尚未接 H2 時，透過測試掛載端或事件觀察驗證 select-device；不得為此直接改 MainLayout。面板可見與正確名稱是 H2 整合驗收。
4. 執行直接相關的既有 layoutStore、placementCheck、deviceOccupancy、useGridViewport 測試。新增測試以手勢互斥、單次提交與取消等實際風險為主。
5. 目前 Vitest 是 node 環境；先盤點現有測試能力。若欠 DOM 環境，不為本單任意擴大依賴或全域配置；用可用瀏覽器驗收並明列自動測試缺口。
6. 修改 Story 時實際開啟預覽、Controls、邊界與 Accessibility；axe 零違規不能替代指標與鍵盤人工檢查。
7. 每項記錄「通過／失敗／未執行」、觀察結果與證據位置。模擬取消、觸控或卸載不能冒稱實體裝置驗收。

## 實際結果

### 正式頁互動

本次曾以獨立瀏覽器腳本對 Vite 正式首頁進行 Chromium 無頭驗收，**29／29 案通過**，無 pageerror。驗證後依使用者要求移除 `src/__tests__/editor/LayoutView.browser.mjs`，不再保留執行說明或可重跑入口；以下結果與截圖保留為歷史驗收紀錄。

原腳本沿用環境既有 Playwright／Chromium，未新增專案套件依賴，且不屬於 `pnpm test` 的 Vitest 測試。移除腳本不影響產品拖曳功能或既有 Vitest 測試。

| 通過群組 | 實際證據 |
| --- | --- |
| 本地預覽／提交 | 同一設備 DOM 不重複、佔格與標籤同步；拖曳中原設備位置、moveDevice 次數及 history 均不變，正常放開恰一次提交 |
| 拒絕與回原位 | 設備重疊、管線佔格衝突皆依 L1 拒絕，無新增 history，預覽清除 |
| 點選與落子 | 設備 emit 實例 ID、空白 emit null；原生 click 連續落子兩次；武裝時搬設備不誤新增，下一次點空白可繼續落子 |
| 平移 | 空白拖曳、中鍵、平移工具、Space 均維持平移；Space 先放開不改變手勢種類、不落子 |
| 門檻／回原格 | 小於 4 px 抖動仍點選，恰 4 px 成為拖曳；拖回原格不提交也不當點選 |
| 取消與重入 | pointercancel 注入、原生 releasePointerCapture 後 lostpointercapture、卸載均不提交，capture／預覽清理；取消後原生落子可恢復 |
| 多指標與按鍵 | 注入第二 pointer 不搶手勢、錯誤按鍵的 pointerup 不提交，右鍵不啟動 |
| 幾何 | filling_machine 在 90／270 度時命中多格邊角，保留抓取偏移、z=3 與 rotation；不同層同 xy 取後繪製設備 |
| 換算／釋放 | offset=(73,41)、zoom=1.5 仍落到正確世界格；注入沒有最後 pointermove 的 pointerup 時使用最終座標 |
| 邊界資料 | 空設備、未知機型、拖曳中移除設備皆無例外；未知預覽 ID 與 null 另在 Story 驗證 |
| 出界與管線 | 拖到 x=-1 允許提交並顯示既有 Error，預覽時 Error 已跟隨；管線座標保留原位 |
| 視覺 | 依使用者最新要求恢復 sky-300，亮／暗模式相同，文字為深色；原外框保留，截圖隨測試更新 |

正常拖曳／點擊採 Playwright 原生 mouse；取消事件、多指標及缺末次 move 的案例明確使用事件注入。選取事件由測試觀察 LayoutView listener，未修改 MainLayout；測試讀取 Vue 開發 instance，因此應使用 pnpm dev，而非 production preview。

### Storybook

- `pnpm storybook --ci --host 127.0.0.1 --no-open` 成功提供畫面。
- 九個 Story 均實際開啟：Connected、Broken、Empty、Dragging、NoDragPreview、UnknownDragDevice、WithinBase、PartialOutside、MultipleOutside。
- Dragging 顯示預覽位置；null／未知 ID 恢復原位置且沒有拿起標記，無元件錯誤。
- Controls 以實際 JSON 編輯將預覽改成 (6,4,0)，圖形同步更新；再輸入 null，設備恢復原位。
- 九個 Story 的 axe-core 元件範圍掃描無 violations（排除頁面 region 規則，因測試對象為元件）；實際開啟 Accessibility 分頁也顯示零 violations。
- 實體滑鼠／觸控、螢幕閱讀器與完整鍵盤無障礙流程未執行；Space 快捷鍵已在瀏覽器回歸涵蓋。H2 面板接收端不在本次範圍。
