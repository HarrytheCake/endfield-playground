# 步驟 4：手動驗收與問題分類

## 目標

在不修改禁止檔案的前提下，確認 Inspector 顯示是否正確，並把上游問題與本工單問題分開。

## 啟動方式

執行：

```powershell
pnpm dev
```

開啟正式 `/` 編輯器，不以 `/dev` 頁作為主要驗收畫面。

## 驗收案例

### 案例 1：未選取

1. 開啟頁面。
2. 確認 Inspector 顯示空狀態。
3. 確認 console 沒有相關錯誤。

預期結果：顯示「未選取設備」。

### 案例 2：既有 mock 設備單選

1. 選取一台既有 mock 設備。
2. 確認名稱與機器資料一致。
3. 確認佔格與 `machines.ts` 一致。
4. 確認耗電與 `machines.ts` 一致。

如果單擊沒有更新 Inspector，改用能觸發 `selection-change` 的框選方式測試。

### 案例 3：多選

1. 框選兩台以上設備。
2. 確認 Inspector 顯示空狀態。
3. 確認不殘留先前單選設備資訊。

### 案例 4：清空選取

1. 先成功顯示一台設備。
2. 點擊畫布空白處或以既有互動清除選取。
3. 確認畫面回到空狀態。

### 案例 5：新放置設備

1. 從工具列放置一台設備。
2. 嘗試選取該設備。
3. 記錄 Inspector 是否能查到機器定義。

若新設備無法顯示，檢查 `node.data.machineType`。英文 `EquipmentType` 與
`getMachine()` 的中文名稱契約不一致屬於上游問題，不在本工單修改範圍。

## 問題分類

| 現象 | 分類 | 本工單是否修正 |
| --- | --- | --- |
| selectedNodeIds 已正確更新，但 Inspector 顯示錯誤 | Inspector 接線或模板問題 | 是 |
| 單擊不更新 selectedNodeIds | FactoryCanvas 選取接線問題 | 否，記錄並回報 |
| 新設備 machineType 為英文而查不到 | 節點資料契約問題 | 否，記錄並回報 |
| machines.ts 的尺寸或耗電錯誤 | codegen／資料問題 | 否，記錄並回報 |
| 多選時殘留上一台資料 | Inspector computed 問題 | 是 |

## 證據

保留一張截圖或不超過 30 秒的錄影，內容至少包含：

- 成功顯示一台既有設備資訊。
- 清空或多選後的空狀態。

## 驗收條件

- 已完成上述主要案例。
- 已將上游問題與本工單問題分開。
- 沒有為了通過演示而修改禁止檔案。
