## 目標與限制

- 本 PR 僅負責 L2／L3 串接，旋轉 action、操作歷史與重疊規則使用 aaaaa 在 #79 提供的 L1 契約。
- `src/store/layoutStore.ts` 與 `src/__tests__/store/layoutStore.rotation.test.ts` 相對 PR 目標分支必須沒有差異；保留 #79 提供的檔案與實作，不刪除檔案。
- 不修改 `GridCanvas.stories.ts` 或 WarningIcon 本體，不自行補寫 L1 action 或由 L2 建立 Command。
- 修改程式須補齊繁體中文 JSDoc；每一步驗證通過後才進入下一步。
- 驗證結果以 Markdown 紀錄，不產生測試圖片、截圖或 JSON 報告。
- 缺少 L1 action 時，先整理契約需求回報 L1 維護者，不自行實作；未獲對外聯絡授權時，先將回報內容提供使用者。

## 步驟 1：確認分支、PR 基準與 #79

執行內容：

- 確認目前分支、未提交變更及遠端追蹤關係，辨識並保留既有分析文件。
- 抓取最新遠端，確認實際 PR 的來源與目標分支，不直接在 master 修改功能。
- 確認 #79 已合入目標分支，閱讀 L1 action、型別及重疊測試。

驗證：

- 紀錄來源／目標分支與提交 SHA，確認 #79 合併提交是目標分支祖先。
- 比較兩個 L1 檔案的分支內容及三點差異，分清檔案內容與 PR 差異。
- 以分析時現況為參考：dev/toby 為 db0c7f8，已 merge #79，兩個 L1 檔案沒有差異；執行時仍需重新確認。

## 步驟 2：整理 rebase 與 L1 檔案差異

執行內容：

- 檢視 dev/toby 的提交圖及既有 merge；保存原始提交 SHA 與必要的本機備份，再依最新目標分支執行 rebase。
- 若重播原提交導致 L1 衝突，逐一採用 #79 在目標分支提供的版本；不可盲用 ours／theirs，因 rebase 的語意容易混淆。
- 保留本 PR 的畫布連線、斷線警示與旋轉入口；若 L1 差異本已為零，不為了移除變更而刪除 action 或測試。

驗證：

- rebase 完成且無未解衝突；檢視重播前後差異，確認未遺失原本的 L2／L3 功能。
- 以最新 PR 目標分支計算，兩個 L1 檔案的內容與三點差異均為零。
- 本步僅處理本機歷史；如後續需 force-with-lease 推送，完成可審閱結果與驗證後再取得授權。

## 步驟 3：收斂 LayoutView 的旋轉呼叫與提示

預計修改：`src/editor/layout/LayoutView.vue`。

執行內容：

- 保留既有選取 ID、四向角度計算、可設定快捷鍵及手勢互斥。
- 僅呼叫 `layoutStore.rotateDevice(device.id, rotation)`；歷史、佔格與埠幾何沿用 L1。
- 移除旋轉重疊會失敗的提示分支，保留 L1 實際拒絕操作時的適當提示。
- 不新增 L2 碰撞阻擋；#79 的重疊行為是允許寫入，由 layoutIssues／驗證標示 E001。

驗證：

- 旋轉路徑中沒有直接變更 store 資料、呼叫 history.execute 或自行建立 Command。
- 沒有以重疊預檢拒絕旋轉；註解與提示符合 #79 契約。
- 缺失設備不會誤轉其他設備，invalid 失敗不顯示成功狀態。

## 步驟 4：逐項驗證正式畫布行為

| 案例 | 預期結果 |
| --- | --- |
| 未選設備按 R | 不變更設備或歷史 |
| 選取非正方設備並旋轉四次 | 回到原角度，尺寸及埠隨角度更新，原點不變 |
| 重新設定快捷鍵、長按 | 新鍵生效，長按不產生非預期重複操作 |
| 文字輸入、設定面板、拖曳、拉線或平移期間 | 不誤觸旋轉 |
| 與其他設備或管線重疊 | 旋轉仍成功，歷史增加一筆；依 L1 衍生結果確認重疊，不顯示旋轉被重疊拒絕 |
| 旋轉導致埠與管線分離 | 管線保留原位，連線狀態及斷線驚嘆號更新 |
| Undo／Redo | 還原／重做角度及衍生狀態，無額外歷史 |
| 設備選取後被移除 | 不誤操作其他設備 |

另追查 E001 從 layoutIssues 到正式 UI 的既有資料流；若只確認 store 有重疊資料，紀錄顯示層是否接入，不宣稱已看到畫面警示，也不擴大本次範圍。

驗證：每個案例記錄操作、結果與適用提交；失敗時先找出 L1 契約或 L2 串接的責任歸屬，不改寫 L1 測試配合 L2。
