## 完成內容

### LayoutView：指標事件與提交

修改 [LayoutView.vue](../../../src/editor/layout/LayoutView.vue)：

- 明確平移優先，再依設備佔格判斷一般左鍵是點設備或空白。
- 沿用 `getDeviceOccupiedCells` 與 footprint 轉換，處理旋轉、多格及不同 z 層的 xy 投影；投影重疊時由後繪製設備優先。
- 一般左鍵以螢幕位移達 4 CSS px 作為拖曳門檻，保留抓取偏移及設備原 z。
- 預覽位置放在 local ref，拖曳過程不寫 store、不產生歷史。
- 正常放開且終點不同原位置時，只呼叫一次 `moveDevice`；失敗清預覽、回原位、不彈窗。
- 點設備 emit `select-device(id)`，點空白 emit `select-device(null)`；單純點選、拖回原格與取消都不提交移動。
- 一般左鍵捕捉來源 SVG，保留 `cell-click` 路徑；中鍵／平移工具沿用容器捕捉。
- 處理取消、失去捕捉、卸載、多指標、錯誤按鍵釋放及尾隨 click 抑制。
- 保留空白拖曳平移、中鍵、平移工具、Space 平移及武裝後的連續點擊落子。
- 出界 ID 由既有 `devicesOutsideBase` 對預覽位置計算，仍只影響 Error 顯示。

### GridCanvas：唯讀預覽與最終樣式

修改 [GridCanvas.vue](../../../src/editor/layout/GridCanvas.vue)：

- 新增唯讀 `deviceDragPreview` prop，包含設備實例 ID 與預覽 position，預設 null。
- 拖曳時只替換該設備的顯示位置，佔格與標籤同步，原位不重複留一台設備。
- null 或未知設備 ID 不影響原有顯示；元件仍無 Pinia／store 相依。
- 更新操作說明及拿起狀態標記。

最終視覺依使用者確認：

- 拖曳填色：亮／暗模式皆為 `sky-300` 淺藍色。
- 外框：沿用原本 `1.5` 實線及正常／出界配色，不加粗、不加虛線。
- 文字：拿起時使用深色文字。

參考圖的藍灰色曾短暫套用，之後依使用者要求恢復先前淺藍色；相關自訂色票及全域 import 已移除，最終 `src/style.css` 無變更。

### Story 與瀏覽器回歸

- [GridCanvas.stories.ts](../../../src/editor/layout/GridCanvas.stories.ts) 新增 Dragging、NoDragPreview、UnknownDragDevice，連同既有六個 Story 共九個情境。
- 曾以 `LayoutView.browser.mjs` 完成 29 項正式首頁瀏覽器驗收；後續依使用者要求移除該腳本，以下測試結果保留為歷史紀錄，不再提供可重跑入口。
- 原腳本沿用環境既有 Playwright／Chromium，未新增套件依賴或修改 lockfile，曾以 Vue 開發 instance 觀察狀態。
- 正常操作使用原生 mouse；取消、多指標及缺少末次 move 等邊界明確採事件注入。
- 色彩檢查等待預覽 DOM 出現後再比對，避免讀到前一個渲染狀態；同時比較原外框顏色、粗細與實線設定。
