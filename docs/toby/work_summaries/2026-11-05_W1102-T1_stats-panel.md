下列為本次接線使用的資料來源；列為來源不代表該檔案有修改。

| 資料 | 執行時來源檔案 | 原始資料或產生方式 |
| --- | --- | --- |

| 設備名稱、尺寸、耗電、來源／終點身分、模式與埠 | [machines.ts](../../../src/data/machines.ts) | [machines.json](../../aaaaa/data/machines.json)、[machine_tags.json](../../aaaaa/data/machine_tags.json)，另有產生器附加的測試用設備定義 |

| 正式加工配方、投入／產出數量、設備模式、環境及加工秒數 | [products.ts](../../../src/data/products.ts) 的 `getRecipesForMachine()` 等 API | [products.json](../../aaaaa/data/products.json)；本次核對為 94 種產品、129 筆配方 |
| 來源設備的預設供應速率 | [layoutStore.ts](../../../src/store/layoutStore.ts) 的 `setDevicePrimaryOutput()` | 設定素材時未指定速率，使用程式預設 `30` 個／分；不是由 materials.ts 決定 |
| 驗證 alerts 與 blocking error | [validationStore.ts](../../../src/store/validationStore.ts) | [useValidation.ts](../../../src/composables/useValidation.ts) 以目前拓撲執行已註冊 detector |

靜態資料由 [generate-src-data.mjs](../../aaaaa/scripts/generate-src-data.mjs) 產生。需要更改設備、素材或配方主資料時，修改對應原始 JSON，再執行 `pnpm generate:src-data`；本次沒有修改這些主資料或重新定義配方。

來源素材選單原本已經讀取 materials.ts，本次沒有替換素材來源，也沒有新增「放置來源設備就自動選第一種素材」的行為；新設備仍需設定產出素材。

## 完成內容與修改檔案

### 正式畫布到引擎

- [MainLayout.vue](../../../src/app/layouts/MainLayout.vue)：由 layoutStore 快照與衍生 connections 建立 computed 拓撲，依序交給 `useValidation()`、`useFlowEngine()`；右側掛載 `<ProductionStats overview />`。
- [useFlowEngine.ts](../../../src/composables/useFlowEngine.ts)：`runFlowEngine(topology?)` 支援外部產線；`useFlowEngine(getTopology?)` 支援響應式來源。不傳參數時保留舊 editorStore 入口。空拓撲也會計算，避免清空後殘留舊結果。
- 引擎監聽拓撲及驗證 alerts，透過 `useTimeoutFn` 合併 150ms 內的連續變更，執行時讀最新資料；scope 結束時取消尚未執行的排程。手動重算使用同一來源，但不取消既有待執行排程。
- [useValidation.ts](../../../src/composables/useValidation.ts)：支援相同拓撲 getter；正式資料已是格子座標，不再次除以 gridSize，並同步更新驗證。無參數舊入口仍保留像素換算。
- 本次沒有修改配方匹配、流量傳播、效率、堵塞或品項統計演算法，也沒有改寫 store 公開介面。

### 右側產耗面板

- [ProductionStats.vue](../../../src/editor/stats/ProductionStats.vue)：讀 flowStore.itemSummary，映射為展示欄位 `id`、`name`、`produce`、`consume`、`profit`；其中 profit 呈現引擎 net，不另行重算。保留中間物及零淨值品項。
- 正式產線初次顯示品項時預設展開，直接呈現生產與消耗數字；舊 Inspector 的完整統計模式保留。
- [Index.vue](../../../src/app/StatsPanel/Index.vue)、[types.ts](../../../src/app/StatsPanel/types.ts)：傳遞 hasDevices 與產品明細，展示元件不直接讀 store。
- [ResultPanel.vue](../../../src/app/StatsPanel/ResultPanel.vue)：使用產品物件副本保存展開狀態，以品項 id 在資料更新及排序後延續使用者選擇，避免修改 props。明細按鈕支援鍵盤與 aria-expanded。
- 產出、消耗及淨值顯示固定一位小數與千分位，完整值保留在 title；「收益」標示改為「淨值」，單位為個／分。
- 依使用者最後指示，只要可見產品清單為空，就顯示「尚未擺放設備」，包含已有設備但尚無產耗摘要的情況；這是空清單提示，不代表重新判定畫布沒有設備。hasDevices=false 時仍先隱藏上一輪摘要。
- [Index.stories.ts](../../../src/app/StatsPanel/Index.stories.ts)：保留既有情境，補上空產線、有設備無摘要、零淨值產線、殘留摘要、小數與動態更新，共 13 個 Story。

### 設備正式配方清單

- [MainLayout.vue](../../../src/app/layouts/MainLayout.vue) 使用 machines.ts 取得設備中文名稱，再按引擎相同的有效模式呼叫 products.ts 的 `getRecipesForMachine()`。
- 將正式配方的 `timeSeconds`、`inputs`、`outputs` 映射為 [MachineCard 型別](../../../src/app/MachineCard/types.ts) 的 `duration`、`input`、`output`，傳入既有 [MachineCard](../../../src/app/MachineCard/Index.vue) 顯示。
- 「目前配方」讀取 flowStore.edgeFlows 的實際正流量入料，重用 `matchRecipeByInputs()`，依設備、模式、環境及素材集合匹配；無匹配或非法鏈路時顯示「—」。不以第一筆配方冒充目前配方。
- MachineCard 與其子元件未修改；正式配方清單透過父層 props 接入。基礎素材來自 materials.ts，加工配方來自 products.ts，兩者用途不同。

## 資料流

```text
layoutStore：devices／pipelines／衍生 connections
    → MainLayout：toTopology()
    → useValidation：驗證結果寫入 validationStore
    → useFlowEngine：讀 machines.ts、products.ts 及目前供料設定
    → flowStore：管線流量、設備效率、品項產耗
    → ProductionStats：轉成展示 props
    → StatsPanel：顯示生產／消耗／淨值及空白提示

選取設備
    → MainLayout：讀 machines.ts 的名稱與模式
    → products.ts：查正式可用配方
    → MachineCard：顯示投入、產出、加工秒數
```
