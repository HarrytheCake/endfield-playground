## 1. 背景與動機

三層架構（L1／L2／L3）目前只存在於長篇文件裡，實務上常見的誤會有三種：以為 L2 是運算層、說不清楚三層各自負責什麼、不確定 Pinia 在哪一層。交檔方式也還沒有共識——用 GitHub 網頁上傳、把檔名當版本、把元件放進 `docs/<自己>/` 都發生過。既有的 `docs/dernoson/L1|L2|L3` 寫得完整，但**完整正是它不被讀完的原因**——對只有 3 小時的人來說，入口太深。

本項要的不是再一份教學，而是一張**半頁、能在會議上唸完、貼在 Discord 置頂**的紙。長版繼續存在，這張紙只負責把人送到正確的門口。

## 2. 使用者（協作者）看得到什麼

新成員拿到一張紙，照著跑得起 `pnpm dev`，知道自己要改的檔在三塊畫面的哪一塊，知道三件事絕對不能做。

## 3. 現況盤點

| 對象 | 現況 | 問題 |
|------|------|------|
| 根目錄 `README.md` | 有環境與指令 | 不談分層與畫面 |
| `docs/dernoson/L1|L2|L3` | 邊界與契約寫得很細 | 篇幅長，低工時者不會讀完 |
| `docs/toby/README.md` | toby 自寫的踩坑筆記 | 個人向，但證明「踩坑清單」有需求 |
| 半頁上手文件 | **不存在** | 本項要補 |

## 4. 技術決策

### 4.1 內容範圍（硬性半頁，超出即刪）

| 段 | 內容 | 行數上限 |
|----|------|----------|
| 1 | 跑起來：`pnpm install` → `pnpm dev` → 開哪個網址 | 4 |
| 2 | 三塊畫面：左上畫布、右側數字與警訊、下方選單；各自對應哪個資料夾 | 6 |
| 3 | 三條硬規則（[A1](./A1_announce_and_baseline.md) §4.1 原文） | 3 |
| 4 | 三件禁止事項（見 §4.2） | 3 |
| 5 | 卡住找誰：一張三列小表（環境／分層／資料） | 4 |

### 4.2 三件禁止事項（原文）

1. **禁止用 GitHub 網頁「Add files via upload」交檔**，一律走本機 commit ＋ PR。
2. **禁止用檔名當版本**（`XxxBtn.vue0811`、`Xxx_final.vue` 皆不收）。
3. **禁止把元件放到 repo 根目錄或 `docs/<自己>/`**，元件一律在 `src/components/<Name>/Index.vue` 或工單指定的既有路徑。

### 4.3 方案比較：放哪裡

| 方案 | 優點 | 缺點 | 採用 |
|------|------|------|------|
| A. 新開 `docs/ONBOARDING.md` | 顯眼 | 又多一個入口，與 dernoson 既有教學重疊 | 否 |
| **B. 放進 `docs/dernoson/` 既有教學開頭** | 不新增入口；主編本來就是守門人 | 需主編同意改自己的檔 | **是** |
| C. 只貼 Discord 置頂 | 零成本 | 無版本、三週後找不到 | 否（但同步貼一份） |

採 B 並同步貼 Discord 置頂；兩處內容以 repo 為準。

> 注意：`docs/dernoson/` 屬主編資料夾，aaaaa 不得直接修改。本項若由 aaaaa 代擬，須以草稿形式交付，由主編貼入。

### 4.4 三塊畫面對照（半頁用的簡表）

| 你看到的區塊 | 資料夾 | 你會改到的檔 |
|--------------|--------|--------------|
| 下方設備選單 | `src/editor/toolbar/` | `ToolbarPanel.vue` |
| 中央畫布 | `src/editor/canvas/`、`src/components/MachineShape.vue` | 由工單指定 |
| 右側數字與警訊 | `src/editor/stats/`、`src/components/StatsPanel/` | `Index.vue` 等既有檔 |
