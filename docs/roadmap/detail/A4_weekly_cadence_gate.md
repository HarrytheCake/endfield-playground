## 1. 背景與動機

過去沒有「每階段分派 → 每週對進度 → 依實際進度改工項」的循環，導致兩件事同時發生：完成定義對資訊小白不可用（不知道自己算不算做完），以及欠帳一路堆到月底才爆開。git 上活躍天極少的成員（多數只有 2–4 個活躍日）尤其需要一個**30 秒就能判定的完成定義**，否則下一次出現又是數週後。

本項把「怎麼算完成」「沒完成怎麼辦」「什麼時候可以改期」寫死，讓週日會不需要每次重新協商規則。

## 2. 使用者（協作者）看得到什麼

每個人在接到工單當下就知道：做完是什麼畫面、要在哪一天前給、沒給會怎樣。

## 3. 現況盤點

| 項目 | 現況 |
|------|------|
| 週日會 | 有在開，議程不固定 |
| 完成定義 | 每張工單各自表述 |
| 延期處理 | 無規則，實務上默默順延 |
| 週中同步 | 無；被動等人回報 |
| 完成率統計 | 無 |

## 4. 技術決策

### 4.1 「30 秒驗收」定義（凍結）

一個工項算完成，必須滿足**別人在 30 秒內、不需要開 IDE、就能確認**：

| 交付型態 | 30 秒證據 |
|----------|-----------|
| 畫面 | 截圖或 ≤30 秒錄影，看得出工單「畫面」欄描述的事 |
| 純函式／資料 | 測試檔通過的輸出，或 dev 頁截圖 |
| 文件 | repo 連結，且檔案在工單指定路徑 |
| 設計稿 | 一張可截的 frame |

「我本機跑起來了」不算證據；「PR 開了」不算完成（合入才算，但延壓不計失敗，見 §4.3）。

### 4.2 週循環（固定）

| 日 | 動作 | 執行者 |
|----|------|--------|
| 週日 | 過上週 → 發本週工單 → 講本階段詞彙 | dernoson |
| 週三／四 | 對「本週尚無回報者」在 Discord 問一句 | aaaaa |
| 週五 | 加分工單的 deadline | 各自 |
| 週六 | 主編預留合入時段；待審 PR 排序 | dernoson |

**週中問一句的規格：** 對象是當週還沒回報過的人（名單每週由 aaaaa 依實際回報情況決定，不預先公布）。內容固定為「本週還做得動嗎，需要切半嗎」，**不問百分比、不催稿**；回「做了／卡住／暫停」任一句都算完成回報。

### 4.3 未完成的處理階梯

| 情況 | 處理 |
|------|------|
| 第一週未演示 | 當日會上切半，下週交較小的一塊 |
| 連續兩週同項未演示 | 換人或降級為加分工單；**不累積罪惡感清單** |
| 已知空窗（考試、個人事務、賽事） | 直接標「暫停」，不計入完成率，不派工；原因不必公開說明 |
| 加分工單未交 | 不計失敗；門檻由工單註明的既有產出頂替 |
| PR 已開但主編無工時合入 | 標「延壓」，計為完成，合入排下週 |

### 4.4 完成率怎麼算

只統計**確定工單**。標「加分」的工單**不列入分母**——把它們算進去只會讓數字難看且失去指導意義。

```text
週完成率 = 已 30 秒驗收的確定工單數 / 當週確定工單數
```

### 4.5 什麼時候可以改期

| 變更 | 需要誰同意 | 是否改版本號 |
|------|------------|--------------|
| 單週小目標挪動 | 週日會當場決定 | 否 |
| 工項在群組內換週 | aaaaa | 否 |
| 月底門檻的必要工項清單變更 | 主編 ＋ aaaaa | **是**（大綱升版） |
| §1.2 已定案項目變更 | 主編 ＋ aaaaa | **是** |

改期一律回寫 [ROADMAP_OUTLINE.md](../ROADMAP_OUTLINE.md) §8 週曆與 §12 版本紀錄，口頭改期不算數。

## 7. 不做

- 不導入專案管理工具（Jira／Notion 看板）；repo 內 markdown 即可
- 不做個人績效排名；完成率是用來調整工項大小的，不是評分
- 不強制每日站會

## 8. 依賴與封鎖

依賴 [A1](./A1_announce_and_baseline.md) 的工單四欄格式。每人的派工上限（時數、一週幾塊）由主編與 aaaaa 依各自回報的可用時間決定，寫在當週工單的 meta 裡。

## 10. 風險與未交頂替

| 風險 | 對策 |
|------|------|
| 主編是唯一合入者，週六時段被吃滿 | §4.3 允許「延壓」計為完成；待審 PR 同時 ≤ 3 |
| 週中同步變成催稿壓力 | 內容固定為「本週還做得動嗎，需要切半嗎」，不問進度百分比 |
| 規則寫了不執行 | 8/30 的 DoD 要求「大綱週曆已更新一次」，用產出證明機制在跑 |

**未交頂替：** 未完成則沿用現況（無固定節奏），但須在 8/30 會上明確記錄，因為 9 月起工項密度上升，缺節奏的成本會顯著放大。
