## 1. 背景與動機

「初步串通、可運行」如果沒有一份逐步劇本，就會在 11/29 當天變成各說各話：有人覺得能放設備就算串通，有人覺得要能匯出才算。主編已在 ROADMAP §5 給出 8 步劇本，本項把它固定為**可執行、可勾選、可在會前自己跑一遍**的形式，並排一次彩排。

彩排排在 11/22 而不是 11/28，是刻意的：留一週修補時間。歷史經驗顯示這類串通演示的失敗多半不是功能沒做，而是資料對不上（缺 `machineType`、缺 handle、缺源素材），這類問題發現後通常一到兩天內可修，但必須先發現。

## 2. 使用者看得到什麼

一場約 3 分鐘、不需要打開 `/dev` 頁的完整演示。

## 4. 技術決策

### 4.1 驗收劇本（凍結，8 步）

| # | 步驟 | 通過條件 | 依賴工項 |
|---|------|----------|----------|
| 1 | 打開網頁 | `pnpm dev` 後畫面正常，無 console error | [A3](./A3_onboarding_onepager.md) |
| 2 | 從下方拉出一個源與一台加工機 | 佔格合理，看得到 port | [B1](./B1_toolbar_real_machines.md)、[B2](./B2_placement_chain.md)、[A2](./A2_grid_and_port_alignment.md) |
| 3 | 源設定一種基礎材料；兩機拉管線（含一個彎） | 連線成立，折線為直角 | [C5](./C5_source_primary_output.md)、[C1](./C1_port_hit_and_draft.md)、[C3](./C3_pipeline_polyline_render.md) |
| 4 | 右側出現該材料的產／耗數字 | 數字非空且會隨畫布變動（允許粗略） | [D1](./D1_stats_item_summary.md) |
| 5 | 把兩機疊在一起 | 右側出現重疊警訊 | [D2](./D2_e001_overlap_alert.md) |
| 6 | 拆掉一條必要管線 | 右側出現缺連接或配方類警訊 | [D3](./D3_recipe_alerts.md) |
| 7 | 匯出 JSON，重新整理後匯入 | 設備與管線都還在 | [D4](./D4_blueprint_json_io.md) |
| 8 | 刪一台或拖移一台 | 畫面跟上（Undo 加分，非硬門檻） | [B5](./B5_delete_single_device.md)、[C4](./C4_move_into_history.md) |

**全部 8 步通過即「初步串通、可運行」。** 步驟 8 的 Undo 為加分，其餘皆為必要。

### 4.2 演示產線的選定

| 要求 | 說明 |
|------|------|
| 節點數 | 3 台（源 → 加工 → 匯出點），不多不少 |
| 材料 | 固體（belt），避免 pipe 相關的額外變數 |
| 配方 | 單一輸入單一輸出，不用多輸入配方 |
| 彎折 | 兩台設備刻意錯開一格，強制產生一個 90 度彎 |

**產線一經選定即凍結**，寫進本檔附錄，所有彩排與正式演示用同一組。這讓「上次可以這次不行」變成可追查的回歸問題。

### 4.3 不開 `/dev` 的理由

驗收劇本明確要求不開 `/dev` 頁。`/dev` 是 L1 的除錯工具，能在那裡跑通只證明引擎正確，不證明主線串通——而串通正是本輪的唯一目標。`/dev` 保留為**除錯備援**：演示失敗時用它區分「引擎錯」還是「接線錯」。

### 4.4 彩排規則

| 項 | 規定 |
|----|------|
| 日期 | 11/22（日） |
| 執行者 | **不是** aaaaa。找一位沒有寫過本輪主線程式的人操作（例如 paper 或 avery） |
| 記錄 | 每步勾選；失敗步驟記下畫面與 console |
| 產出 | 一份失敗清單，附「錯在資料／錯在接線／錯在引擎」分責 |

由非開發者操作是關鍵：寫程式的人會下意識避開已知的坑。
