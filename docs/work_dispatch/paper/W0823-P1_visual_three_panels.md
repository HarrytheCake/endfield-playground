## 2. 為何是你、範圍怎麼切

| 依據 | 結論 |
|------|------|
| 本週可做 | UI 視覺稿（Figma） |
| 本週不做 | **任何程式**、資料整理、數學 → 硬禁 |
| 時數規劃 3–5h | 只做「對齊三塊＋標關鍵 frame」，不做整本 UI kit／全元件庫 |
| 要避開的失敗模式 | Figma 權限／匯出摩擦 → 允許用既有 workaround；以能進 repo 的 `.fig` 為準 |
| 專案風險 | 稿若無人翻成元件會停在 `docs/paper/` → 本週工單**標註對接對象**，但不要求你教他們寫 code |
| 沿用現況 | 你既有的「只推 `.fig`、不碰程式」節奏維持不變 |

**本週不做：** 正式機器立繪、管線精緻風格（10 月 C3）、完整 design token 進 `src/`、Vue 教學。

模擬器介面在 roadmap 裡固定講「三塊」——請以這三塊為本週對齊範圍：

| 你畫的區域 | 使用者在幹嘛 | 之後誰可能照著做（你不用管實作） |
|------------|--------------|----------------------------------|
| **下方選單** | 挑要放哪一台機器 | 約 9/6 起：工具列真機器（B1）；L3 可能是 goodmorning／MBD |

中央畫布維持示意即可（互動是 L2 的事）；本週你的守備範圍就是上表這三塊。

外觀聽你；**功能做多少、哪週上線**聽 roadmap（主編已定）。若稿上的功能超前（例如完整藍圖存檔 UI），標成「以後」即可，**不要**要求工程本週做完。

## 5. 步驟（對齊 3–5h）

### 5.1 對齊三塊（建議 ≤3h）

1. 在主稿中標出或整理：**下方選單**、**右側資訊／警訊**（中央畫布可維持示意）
2. 選單側請至少表達：分類感（Tab 或分區）、卡片上有**名稱**與**佔格示意**（例如「3×2」文字即可；**正式圖資源本週不做**）
3. 右側請至少表達：標題區＋一條「警訊／提示」列的層級（文案可用假字；重點是層級與位置）

### 5.2 標出可驗收 frame（≤1h）

依 A4「設計稿 30 秒驗收」：別人不必開 IDE，只看一張圖就知道你做完了。

請在稿內（或 Discord）點名 **2–3 個 frame**，例如：

| # | 建議 frame | 用途 |
|---|------------|------|
| 1 | 下方選單（含 1–2 張假卡片） | 給 B1／L3 對齊；本週 goodmorning 正在做卡片 mock |
| 2 | 右側資訊或警訊列表 | 給 B4／D1／D2 對齊；本週 MBD 要做右側空狀態，有 frame 他就照著做 |
| 3 | （可選）頂欄或整頁三塊總覽 | 給週會演示 |

### 5.3 交付進 repo

1. 更新 `docs/paper/*.fig` 後交 PR 或依你慣例推分支請 dernoson 合入  
2. Discord 貼：Figma 連結 **或** 上述 frame 截圖  
3. （可選）`docs/paper/README.md` 兩行寫：「本週關鍵 frame：…」——兩行就夠，**不要**寫成長文

Commit 訊息可用中文描述設計變更；若仍不熟 git，把檔給 dernoson 代推也可，但**內容必須是你的稿**。
