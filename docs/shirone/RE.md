# CR-03 驗證系統草案

## 核心抽象

設備與管線統一視為**節點**，每個節點有三個面向：

- **連接**：input / output 的配對關係
- **流量**：流過節點的品項與速率
- **position**：節點在空間中的座標與尺寸

---

## 兩條獨立的驗證路徑

狀態變更後，兩條路徑完全並行執行，結果合併後一次性更新警示狀態。

```
狀態變更
  ├─ 路徑 A：連接 → 流量
  │    連接合法性
  │    ↓（有阻斷性問題的節點跳過）
  │    流量計算（CR-04）
  │    ↓
  │    流量合法性
  │
  └─ 路徑 B：position
       空間合法性

  兩條路徑完成 → 合併 → 更新警示
```

---

## 各層驗證的問題

### 路徑 A — 連接層

有問題的節點跳過流量計算。

- 相連的兩個接口，type 是否匹配？
- 同一個 output 是否接出超過一條管線？
- 哪些 input / output 懸空？

### 路徑 A — 流量層

- 流入這個 input 的品項，是否符合節點的配方需求？
  - 否 → 該節點跳過計算，下游視為無輸入繼續算
  - 是 → 繼續往下
- 流量速率是否超過節點的容量上限？
- 節點的實際效率是多少？

### 路徑 B — position 層

- 兩個節點的空間是否重疊？
- 管線路徑是否穿越其他節點的空間？
- 節點是否在供電覆蓋範圍內？
- 整體供電是否透支？
