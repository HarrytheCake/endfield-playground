# L2 容器層 — 總覽

**所屬層級：** L2（Container Layer）
**負責成員：** harry（Owner）、toby（Senior IC）
**對應 CR：** CR-01、CR-02（合併區塊）；橫向支援 CR-03 / CR-04 / CR-05 / CR-08
**文件版本：** v0.1

---

## 1. L2 在三層架構中的定位

```
L1 基礎層       Pinia stores、型別、FlowEngine、history、graph utility
                 不寫真實 UI，最多 debug 用測試頁
                 ▲ 提供 state / actions / selectors
                 │
L2 容器層       直接消費 store；主畫面 layout、互動 wiring
                 對下層只透過 props / events 溝通
                 ▼ 把 store state map 成 plain props
L3 UI 元件層    純展示元件，不 import 任何 store
```

L2 是「翻譯層」：把 L1 的 stores 翻譯成 L3 看得懂的 props，把 L3 拋出的 events 翻譯成對 L1 的 actions 呼叫。

---

## 2. 硬規則中與 L2 直接相關的條款

| 規則 | 對 L2 的意義 |
|---|---|
| L3 禁止 `import { useXxxStore }` | L2 必須把所有 store state 先 map 成 plain props 才能傳給 L3 |
| L1 不寫真實 UI | 互動樣板（template / setup script 中的事件流）必須在 L2 完成，不能塞回 L1 |
| **L2 不做純視覺樣式調整** | 顏色、字級、圓角、padding、icon 配置全部是 L3 工作；L2 只在 wrapper 上放 layout 級 class（grid、flex、定位）|

> 「純視覺樣式」的判準：若改動只影響外觀、不改變行為 / 介面，就是 L3 的事。L2 改 class 的合理理由只有「容器級 layout」與「條件 class 切換以反映 store 狀態（再透過 prop 傳給 L3）」。

| **CR-08 歷史** | Ctrl+Z / Ctrl+Y 全域快捷鍵綁定，呼叫 `historyStore.undo() / redo()`；讀取 `canUndo / canRedo` 餵 UI（按鈕 disable 等）。**Command 由 L1 store action 內部自動產生並推入歷史，L2 不需要自己組 Command、不呼叫 `execute()`**。注意：`useShortcuts()` composable 已在 MainLayout 啟動，Ctrl+Z/Y、Delete、Space 等預設快捷鍵已綁好，L2 不需重複註冊 |

### 4.7 Command 歸屬規則（重要）

- 上述 §4.2 列出的 8 個 high-level action **內部會自動產生對應 Command 並推入歷史**，呼叫一次就會多一筆歷史項目。
- L2 直接呼叫這些 action，**不需要 import `historyStore.execute()`、不需要 import `createMacroCommand`**（後者於程式碼中亦不存在）。
- L2 若發現某個互動沒有對應的 L1 high-level action（例如跨 store 的原子操作），應反映給 L1 補上 high-level action（由 L1 在內部把多個 mutation 組合成單一歷史項目），**而不是在 L2 自己組 Command**。
- L2 對 historyStore 的互動只有兩種：Ctrl+Z / Ctrl+Y 快捷鍵呼叫 `undo() / redo()`（已由 `useShortcuts()` 處理）；以及讀取 `canUndo / canRedo` 用於 UI 狀態（按鈕 disable 等）。

L2 **不允許**直接改 store 內部 state（避開 actions），所有變更都要走 L1 提供的 action。

## 5. L2 對 L3 的交付介面

### 5.1 規範

1. **永遠先 map**：不直接把 `FactoryNode` 或 `FactoryEdge` 物件原封不動丟給 L3；先在 L2 的 `<script setup>` 用 `computed` 整理成 plain props。
2. **狀態用 prop**：選取狀態、警示等級、流量數值、是否為拿起預覽 ⋯⋯ 都是 prop。
3. **行為用 emits**：滑鼠事件、鍵盤事件、按鈕點擊一律 emit，L2 接到後決定要呼叫哪個 store action。
4. **Props 必須 readonly**：L3 拿到的物件不可變更，內部不可呼叫 store actions。
5. **TypeScript 介面先行**：每個 L3 元件交付前先定義好 `defineProps<P>()` 與 `defineEmits<E>()`，介面定稿後 L3 才開始實作。

### 5.2 介面範例

```typescript
// L3：<DeviceNode>
interface DeviceNodeProps {
  uid: string
  deviceId: string
  x: number
  y: number
  rotation: Rotation                // 0 | 1 | 2 | 3（旋轉次數，每次 90°）
  size: { w: number; h: number }
  ports: ReadonlyArray<{ id: string; x: number; y: number; type: 'conveyor' | 'pipe' }>
  selected: boolean
  hovered: boolean
  isHeldPreview: boolean
  hasOverlap: boolean            // 來自 validation，決定是否紅色高亮
  alertLevel: 'none' | 'warning' | 'error'
  efficiency: number | null      // 0~1，null 表示沒算（有 Error）
  activeRecipeName: string | null
}

interface DeviceNodeEmits {
  (e: 'pointerdown', ev: PointerEvent): void
  (e: 'pointerup', ev: PointerEvent): void
  (e: 'longpress', payload: { gridX: number; gridY: number }): void
  (e: 'portClick', portId: string): void
}
```

```typescript
// L3：<PipelineEdge>
interface PipelineEdgeProps {
  uid: string
  type: 'conveyor' | 'pipe'
  points: ReadonlyArray<{ x: number; y: number }>  // 含起終點的完整座標序列
  selected: boolean
  alertLevel: 'none' | 'warning' | 'error'
  flowPerMin: number | null
  invalidSegmentIndices: ReadonlyArray<number>     // 90 度違規線段（給 draft 用）
}

interface PipelineEdgeEmits {
  (e: 'click', ev: MouseEvent): void
  (e: 'segmentClick', segmentIndex: number, gridPos: { x: number; y: number }): void
}
```

### 5.3 Mock data

L2 必須為每個 L3 元件提供 mock 範例（放在 `*.stories.ts` 或 `__mocks__`），讓 L3 開發者不需啟動 store 就能獨立預覽。

## 6. 工作流程

L2 任一互動上線前的順序：

1. **跟 L1 對齊 store 簽名**：確認所需的 high-level action 名稱與型別；每個 L2 互動都應對應到一個（或一組）會自動進歷史的 L1 action。缺的請 L1 補（不要在 L2 自己組 Command）。
2. **設計 L3 props / emits 介面**：寫到 `docs/dernoson/L2/interfaces/`（或 element 自己的 `.d.ts`），與 L3 對齊後鎖定。
3. **L2 wiring 實作**：在 container 內部用 `computed` 把 store state 映射成 props，用 emits handler 呼叫 L1 action（action 自動進歷史）。
4. **快捷鍵綁定**：Ctrl+Z / Ctrl+Y 綁到 `historyStore.undo() / redo()`；其他快捷鍵綁到對應 L1 action。
5. **手動驗證**：對著 spec 第 7 節（驗證方式）逐項過，特別檢查每個操作都能 Ctrl+Z 還原。

## 7. 為什麼 CR-01 與 CR-02 合併

兩個 CR 在 L2 層耦合過深，分兩個 team 必定打架。耦合點：

| 耦合點 | 跨界內容 |
|---|---|
| **autoNode 同時寫兩個 store** | 分流器 / 匯流器 / 物流橋是「自動產生的 FactoryNode」，需要同時更新 `editorStore` 的 nodes 與 edges，且必須在一個歷史項目內（由 L1 high-level action 內部處理；Phase 1 autoNode 自動生成尚未實作）|
| **設備擺放觸發自動連接** | CR-01 設備放置後若 port 正對既有 dangling 管線，CR-02 要立刻補上 `FactoryEdge`；屬於同一個歷史 entry（同樣由 L1 action 內部包）|
| **設備移動時管線跟隨** | CR-01 拖動設備、CR-02 的 edge 端點跟著動，可能引發路徑違法（90 度斷掉）或衝突（穿過其他管線）|
| **框選複製含管線** | CR-01 框選結果 + CR-02 框選範圍內的 edges 一併複製，新舊 uid 對照表必須同步 |

合併後由 harry 統一 own 全部 PR，toby 吃技術深度，避免 CR-01 / CR-02 PR 互相阻塞。
