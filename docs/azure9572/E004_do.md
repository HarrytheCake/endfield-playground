# E004 實作紀錄：輸入缺失 (Missing Input)

## 任務背景與目標
根據 CR-09「配方警示」的規格需求（`spec/09_recipe_warning.md`），需要實作 E004 錯誤偵測器（Detector）。
- **觸發條件**：設備的當前配方明確要求輸入，但該設備未接入任何管線。
- **類型**：Error（會阻斷後續的流量估算）。
- **階段限制**：在 Phase 1 實作中，我們採用「設備層級」判斷，只要有任何一條管線接入該設備，即視為通過初步檢驗。

## 演算法與實作細節

### 1. 偵測邏輯 (`src/lib/validation/detectors/E004_missingInput.ts`)
Detector 被設計為一個接收 `ValidationContext` 並回傳 `Alert[]` 的純函式。演算法步驟如下：
1. **遍歷所有設備**：從 `ctx.devices` 中取得畫布上所有已部署的節點。
2. **取得設備與配方定義**：
   - 透過 `device.data.machineType` 以及 `ctx.getDef()` 取得設備的靜態定義。
   - 透過 `device.data.recipeIndex`（預設為 0）以及 `getRecipesForMachine()`，取得目前設備選用的配方 (`RecipeDef`)。
3. **判斷是否需要輸入**：
   - 檢查 `recipe.inputs` 是否存在且長度大於 0。若無輸入需求，則直接跳過。
4. **驗證管線接入狀態**：
   - 遍歷 `ctx.connections`（所有管線），檢查是否存在任何一條管線的終點（`target`）指向該設備的 `id`。
   - `const hasIncomingConnection = connections.some(edge => edge.target === device.id);`
5. **產出警示 (Alert)**：
   - 若 `hasIncomingConnection` 為 `false`，代表未接入任何管線，則產生一筆 `E004` 的 `error` 等級警示，並將 `relatedDeviceUids` 指向該設備。

### 2. 測試案例 (`src/__tests__/lib/validation/detectors/E004_missingInput.test.ts`)
透過 `vitest` 撰寫了 4 個測試案例來驗證純函式的行為：
- **H1**：無設備時，不應產生錯誤。
- **H2**：設備配方不需要輸入時，未接管線不應產生錯誤。
- **H3 (觸發情況)**：設備配方需要輸入，且未接管線時，應正確產生一筆 E004 錯誤。
- **H4 (正常情況)**：設備配方需要輸入，且已有管線 (`target === device.id`，且 `portType: 'item'`) 接入時，不應產生錯誤。

*(註：測試中使用了 `vi.mock` 替換 `getRecipesForMachine` 以穩定模擬需要與不需要輸入的測試情境。)*
