# W003 (輸出阻塞) 實作文件

## 1. 任務目標
實作 CR-09 中的 `W003` Detector，用於偵測管線的輸出端是否因為下游無法吞吐而發生阻塞，無法排出全部流量。

## 2. 參考檔案
*   `src/types/validation.ts`: 提供了 `ValidationContext`、`Detector` 介面與 `Alert` 型別定義。
*   `src/lib/validation/detectors/W003_outputCongested.ts`: 實作邏輯的主要程式碼位置。

## 3. 使用的資料結構
*   **`ctx.congestedEdges` (`Set<string>`)**: 一個 Set 集合，裡面存放著所有被判定為「發生阻塞」的管線 (Connection) ID。這個資料同樣是在 FlowEngine 完成計算後，擴充進入 `ValidationContext` 內的。
*   **`ctx.connections` (`FactoryEdge[]`)**: 畫布上的所有管線連線，主要用於反查阻塞管線的詳細資訊（如發送端設備）。

## 4. 演算法與程式碼邏輯
相較於 W002 需要進行流量的加總計算，W003 的邏輯極為精簡，因為最核心的「阻塞判定」已經由 FlowEngine 處理並記錄在 `congestedEdges` 裡了。Detector 只需要負責將這份名單轉換為警示 (Alert)。

演算法步驟如下：

1.  **前置驗證 (Guard Clause)**:
    檢查 `ctx.congestedEdges` 是否存在。若不存在，代表系統尚未進行流量計算，無法得知阻塞狀況，此時直接 `return []`。

2.  **遍歷阻塞集合**:
    透過 `for...of` 迴圈，遍歷 `ctx.congestedEdges` 中的每一個管線 ID (`edgeId`)。

3.  **反查管線與關聯設備**:
    使用 `Array.prototype.find()` 在 `ctx.connections` 裡尋找 `id === edgeId` 的原始管線資料 (`connection`)。
    透過原始管線資料，我們可以得知這條阻塞管線是從哪個設備出發的（即 `connection.source`）。

4.  **產生警示**:
    針對每一條找到的阻塞管線，建立一筆對應的 `Alert` 物件：
    *   `level`: 設為 `'warning'`
    *   `code`: 設為 `'W003'`
    *   `message`: 提示「管線輸出阻塞，無法排出全部流量」。
    *   `relatedDeviceUids`: 放入 `connection.source` (發送端設備 ID)，因為是這個設備排出的東西卡在管線上了。
    *   `relatedConnectionUids`: 放入 `edgeId`，讓 UI 可以針對發生阻塞的特定管線做出視覺提示（例如閃爍）。
    *   將產生的 Alert 加入陣列中統一回傳。
