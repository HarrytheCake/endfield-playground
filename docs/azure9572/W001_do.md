## 1. 背景與修正動機

在既有實作中，`W001_unmatchedMaterial` 存在以下幾項缺陷：

1. **配方匹配為「子集判斷」（`every`）**：
   原程式碼使用 `recipe.inputs.every((input) => incomingItemIds.has(input.itemId))`。若加工機僅需材料 A，但上游同時送入材料 A 與材料 B（多餘材料），現行邏輯會判為合格，導致「多餘材料」未能正確觸發 W001 警示。依 D3 §4.3 及 FlowEngine V9 語意，應改為**「輸入種類集合完全吻合（Exact Set Match）」**。
2. **`visited` 跨入邊共用問題**：
   在原 `getIncomingItems` 中，走訪目標設備的多條入邊共用同一個 `visited: Set<string>`。當同一上游同時接出多條管線至下游，或上游不同分流器背後匯流自相同來源時，後續入邊會在 `visited.has(edge.source)` 被直接跳過，導致下游漏收集該路徑的品項。
3. **分流器名稱比對備註**：
   經查驗 `src/types/machine.ts` 與 `src/data/machines.ts`，目前機器定義僅有分類標籤 `tags: ['物流設備']`，尚無專屬旗標（flag）。因此依工單指示保留分流器名稱比對 `machineDef.name === '分流器' || machineDef.name === '管道分流器'`（兼顧 id 比對），並於註解與本實作紀錄加註「**暫時沿用名稱比對**」。

## 2. 演算法與核心架構

### 2.1 集合完全吻合（Exact Set Match）
定義集合等價判定函式 `itemSetsEqual(a, b)`：
- `a.size === b.size`
- `a` 中的每個品項皆存在於 `b` 中
任一配方之需求品項集合 `recipeInputs` 與流入品項集合 `incomingItemIds` 必須大小相等且項目完全一致，才視為吻合。多餘材料或缺漏材料均會導致匹配失敗並發出 W001。

### 2.2 獨立入邊走訪（Per-Edge Traceback）
- 對目標設備的每條入邊（`inEdge`），獨立啟動 `traceEdgeItems` 回溯走訪。
- 初始傳入 `visited = new Set([targetId])` 作為走訪路徑保護：
  - 避免圖形中若有迴路（如 `A -> B -> A`）造成無窮遞迴。
  - 避免反向迴路回連自身目標節點。
  - 各入邊之間互不影響，同一上游節點提供多路輸入時，所有路徑的品項皆能正確收集。

### 2.3 邏輯流程圖

```mermaid
flowchart TD
    Start([走訪 ctx.devices 中的每個 device]) --> GetDef[取得設備定義 machineDef]
    GetDef --> CheckDef{machineDef 是否存在?}
    CheckDef -- 否 --> Skip[略過]
    CheckDef -- 是 --> CheckSource{is_source == true 或 input_ports 為空?}
    CheckSource -- 是 --> Skip
    CheckSource -- 否 --> CheckRecipes{是否有可用配方?}
    CheckRecipes -- 否 --> Skip
    CheckRecipes -- 是 --> CheckEdges{入邊 connections 數量 == 0?}
    CheckEdges -- 是 (無入邊) --> SkipEdge[略過: 交給 E004 處理]
    CheckEdges -- 否 (有入邊) --> CollectItems[逐入邊走訪: traceEdgeItems<br>收集 incomingItemIds]
    CollectItems --> MatchRecipes{是否存在任一配方<br>itemSetsEqual(recipeInputs, incomingItemIds)?}
    MatchRecipes -- 是 (集合完全吻合) --> Pass[正常，不發警告]
    MatchRecipes -- 否 (不符/有多餘材料) --> Alert[產出 W001 Warning Alert]
    Alert --> Next[下一個設備]
    Pass --> Next
    Skip --> Next
    SkipEdge --> Next
    Next --> End([結束走訪，回傳 Alert 陣列])
```

## 3. 程式碼異動摘要

1. **`src/lib/validation/detectors/W001_unmatchedMaterial.ts`**：
   - 實作 `itemSetsEqual` 純函式。
   - 重構 `getIncomingItems` 與 `traceEdgeItems`，以路徑 Set 隔離跨入邊走訪，防止迴路無限遞迴。
   - 保留分流器比對並補全註解說明。
   - 支援 `ctx.getDef` 與模式查詢。
2. **`src/app/dev/ValidationTest.vue`**：
   - 引入並註冊 `W001_unmatchedMaterial`。
   - 新增測試按鈕：
     - `⚡ 新增加工機連線（粉碎機 ➔ 精煉爐，觸發 E004+W001）`（加工機無輸入報 E004，下游材料不符報 W001）。
     - `🎯 新增純粹 W001（源機 ➔ 精煉爐，僅 1 筆 W001，無 E004）`（上游為源類設備物品輸出口，E004 略過源機，下游僅觸發 1 筆 W001 Warning）。
     - `⚡ 新增多餘材料的連線設備（Exact Set Match 觸發 W001）`（送入雙材料至單材料下游，即時觸發 W001 Warning）。
   - 右側新增管線清單展示（`Editor Connections`），並升級「清空所有設備與管線」按鈕。
3. **`src/__tests__/lib/validation/detectors/W001_unmatchedMaterial.test.ts`**：
   - 擴充 mock 資料（增加 `test_producer_AB` 與 `管道分流器` 定義）。
   - 保留既有 T1 ~ T6 案例。
   - 新增 T7 ~ T14 案例（包含多餘材料觸發 W001、多輸入配方完全吻合、缺少材料、多路同源輸入不被略過、跨分流器匯流、管道分流器穿透、圖形回路保護、源節點 primaryOutput 傳遞）。
