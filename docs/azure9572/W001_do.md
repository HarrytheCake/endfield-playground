## 1. 背景與修正動機

在既有實作中，`W001_unmatchedMaterial` 存在以下幾項缺陷：

1. **配方匹配為「子集判斷」（`every`）**：
   原程式碼使用 `recipe.inputs.every((input) => incomingItemIds.has(input.itemId))`。若加工機僅需材料 A，但上游同時送入材料 A 與材料 B（多餘材料），現行邏輯會判為合格，導致「多餘材料」未能正確觸發 W001 警示。依 D3 §4.3 及 FlowEngine V9 語意，應改為**「輸入種類集合完全吻合（Exact Set Match）」**。
2. **`visited` 跨入邊共用問題**：
   在原 `getIncomingItems` 中，走訪目標設備的多條入邊共用同一個 `visited: Set<string>`。當同一上游同時接出多條管線至下游，或上游不同分流器背後匯流自相同來源時，後續入邊會在 `visited.has(edge.source)` 被直接跳過，導致下游漏收集該路徑的品項。
3. **導流設備範圍與名稱比對備註（W1011-Z2 ①）**：
   凡是只負責搬運、不加工的物流設備，回溯時都要直接轉送上游品項。除了分流器外，將**匯流器、管道匯流器、物流橋、管道橋**一併納入 `ROUTING_MACHINE_NAMES` / `ROUTING_MACHINE_IDS`，統一以清單檢查取代個別判斷，並保留「目前機器無專屬 flag，暫時以清單比對」之註解說明。
4. **驗證頁清空命令模式對齊（W1011-Z2 ②）**：
   `ValidationTest.vue` 中的 `testClearDevices` 移除直接賦值 `editorStore.edges = []`，改完全透過 `editorStore.removeDevices(allUids)` 的 Command Pattern 刪除節點連帶之管線，確保不破壞 Undo/Redo 歷史堆疊。
5. **目前模式限定比對（W1011-Z2 ③ / A-5 裁定）**：
   設備必須先選擇模式，因此 W001 必須根據**目前模式**匹配配方，不得退回所有模式。移除 `allRecipes.length === 0` 時退回全部模式的 fallback 邏輯；若未指定 `machineMode` 則依 `getMachineMode` 預設為 `modes[0]`（與 E004 統一）；若該模式查無任何配方則不報 W001。

## 2. 演算法與核心架構

### 2.1 集合完全吻合（Exact Set Match）
定義集合等價判定函式 `itemSetsEqual(a, b)`：
- `a.size === b.size`
- `a` 中的每個品項皆存在於 `b` 中
任一配方之需求品項集合 `recipeInputs` 與流入品項集合 `incomingItemIds` 必須大小相等且項目完全一致，才視為吻合。多餘材料或缺漏材料均會導致匹配失敗並發出 W001。

### 2.2 獨立入邊走訪（Per-Edge Traceback）
- 對目標設備的每條入邊（`inEdge`），獨立啟動 `traceEdgeItems` 回溯走訪。
- 初始傳入 `visited = new Set([targetId])` 作為走訪路徑保護：
  - 避免圖形中若有迴路（如 `A -> B -> A`）造成無窮遞迴。
  - 避免反向迴路回連自身目標節點。
  - 各入邊之間互不影響，同一上游節點提供多路輸入時，所有路徑的品項皆能正確收集。
- 若遇導流設備（分流器、匯流器、物流橋等），直接向上遞迴收集所有入邊之品項。

### 2.3 邏輯流程圖

```mermaid
flowchart TD
    Start(["走訪 ctx.devices 中的每個 device"]) --> GetDef["取得設備定義 machineDef"]
    GetDef --> CheckDef{"machineDef 是否存在?"}
    CheckDef -- 否 --> Skip["略過"]
    CheckDef -- 是 --> CheckSource{"is_source == true 或 input_ports 為空?"}
    CheckSource -- 是 --> Skip
    CheckSource -- 否 --> GetMode["依 device.data.machineMode 取得目前 mode<br>未填則預設 modes[0]"]
    GetMode --> QueryRecipes["查詢該 mode 下之配方 allRecipes"]
    QueryRecipes --> CheckRecipes{"allRecipes 是否為空?"}
    CheckRecipes -- "是（無配方／導流設備）" --> Skip
    CheckRecipes -- "否（有配方）" --> CheckEdges{"入邊 connections 數量 == 0?"}
    CheckEdges -- "是（無入邊）" --> SkipEdge["略過: 交給 E004 處理"]
    CheckEdges -- "否（有入邊）" --> CollectItems["逐入邊走訪: traceEdgeItems<br>遇導流設備持續回溯，收集 incomingItemIds"]
    CollectItems --> MatchRecipes{"是否存在任一配方<br>itemSetsEqual(recipeInputs, incomingItemIds)?"}

    Alert --> Next["下一個設備"]
    Pass --> Next
    Skip --> Next
    SkipEdge --> Next
    Next --> End(["結束走訪，回傳 Alert 陣列"])
```

## 3. 程式碼異動摘要

1. **`src/lib/validation/detectors/W001_unmatchedMaterial.ts`**：
   - 實作 `itemSetsEqual` 純函式。
   - 重構 `getIncomingItems` 與 `traceEdgeItems`，以路徑 Set 隔離跨入邊走訪，防止迴路無限遞迴。
   - 擴充 `ROUTING_MACHINE_NAMES` 與 `ROUTING_MACHINE_IDS`，將分流器、匯流器、物流橋（含管道版）統一納入導流設備。
   - 依 A-5 裁決，限定依 `getMachineMode(machineDef, device.data?.machineMode)` 匹配配方，移除全部模式 fallback。
2. **`src/app/dev/ValidationTest.vue`**：
   - 引入並註冊 `W001_unmatchedMaterial`。
   - 修正 `testClearDevices()`：移除 `editorStore.edges = []`，完全經由 `removeDevices` 走 Command 模式。
   - 提供「新增純粹 W001」、「多餘材料連線」等測試按鈕與連線展示。
3. **`src/__tests__/lib/validation/detectors/W001_unmatchedMaterial.test.ts`**：
   - 擴充 mock 資料，支援所有導流設備以及多模式切換模擬。
   - 包含 T1 ~ T14 基礎與邊界測試。
   - 補足 W1011-Z2 要求之 T15 ~ T18 測試（經過匯流器、經過物流橋、合流、模式切換）。
