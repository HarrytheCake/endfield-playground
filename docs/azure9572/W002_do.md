# W002 (輸入不足) 實作文件

## 1. 任務目標
實作 CR-09 中的 `W002` Detector，用於偵測設備的輸入端流量是否小於其配方所定義的理論需求。包含完全未接管線的狀況，其輸入流量視為 0，同樣會觸發此警示。

## 2. 參考檔案
*   `src/types/validation.ts`: 提供了 `ValidationContext`（Detector 的執行環境）、`Detector` 介面，以及產出的 `Alert` 資料格式。
*   `src/types/flow.ts`: 提供了 `EdgeFlow` 型別，用來理解管線實際流量的資料結構。
*   `src/data/products.ts`: 呼叫其中的 `getRecipesForMachine` 函式，用於取得各設備可用的配方陣列。
*   `src/lib/validation/detectors/W002_insufficientInput.ts`: 實作邏輯的主要程式碼位置。

## 3. 使用的資料結構
*   **`ctx.edgeFlows` (`Map<string, EdgeFlow>`)**: 以管線 (Connection) ID 為鍵值，記錄每一條管線實際傳輸的品項 (`itemId`) 以及傳輸速率 (`rate`)。這個欄位是在 FlowEngine 計算後動態擴充加入 `ValidationContext` 的。
*   **`ctx.devices` (`FactoryNode[]`)**: 畫布上的所有設備節點。
*   **`ctx.connections` (`FactoryEdge[]`)**: 畫布上的所有管線連線。
*   **`RecipeDef`**: 透過設備類型與選擇的 index 取得配方後，存取其 `inputs` 陣列（包含 `itemId` 和單次消耗量 `quantity`）與 `timeSeconds`（單次加工耗時）。

## 4. 演算法與程式碼邏輯
W002 被設計為一個無副作用的純函式，其演算法步驟如下：

1.  **前置驗證 (Guard Clause)**:
    由於 `W002` 必須依賴 FlowEngine 的計算結果，首先檢查 `ctx.edgeFlows` 是否存在。若不存在，代表系統處於尚未進行流量計算的階段，此時無法判斷流量充足與否，直接 `return []`。

2.  **遍歷設備與獲取配方**:
    *   透過 `for...of` 迴圈遍歷 `ctx.devices`。
    *   加入防呆機制：`if (!device.data || !device.data.machineType) continue;`，避免未完整的資料結構造成 TypeScript 錯誤。
    *   呼叫 `getRecipesForMachine(device.data.machineType)` 取得所有配方，並根據 `device.data.recipeIndex` 取得目前啟用的配方。
    *   若該設備沒有配方，或配方中 `inputs` 陣列為空（不需要輸入），則提早跳過 (`continue`)。

3.  **計算需求與比對實際供給**:
    針對該配方需要的每一個輸入項目 (`input` in `recipe.inputs`)：
    *   **理論需求速率 (Demand Rate)**: 
        公式為 `input.quantity * (60 / recipe.timeSeconds)`，算出每分鐘需要的該品項數量。
    *   **實際供給速率 (Actual Supply Rate)**: 
        初始設為 0。接著遍歷 `ctx.connections`，找出所有 `target` 等於該設備 ID 的管線。
        若是接往該設備的管線，便從 `ctx.edgeFlows` 中透過管線 ID 取得流量資訊 `edgeFlow`。
        若 `edgeFlow.itemId === input.itemId`，則將 `edgeFlow.rate` 累加至實際供給速率中。
    *   **比較判定**:
        為了避免浮點數精確度問題，使用 `actualSupplyRate < demandRate - 0.001` 作為判斷條件。
        若實際供給量確實小於理論需求量，則判定為「輸入不足」。

4.  **產生警示**:
    當判定為輸入不足時，建立一筆 `Alert` 物件：
    *   `level`: 設為 `'warning'`
    *   `code`: 設為 `'W002'`
    *   `message`: 包含設備名稱、缺失品項名稱、理論需求量與實際供給量，方便使用者閱讀。
    *   `relatedDeviceUids`: 包含該設備 ID，以便 UI 面板可以聚焦或畫紅框。
    *   最後將這筆 Alert 加入陣列中回傳。
