# V9-A1 — 範圍與定案

**對應工項：** V9-A1  
**狀態：** 完成（文件定案）  
**日期：** 2026-08-02

---

## 1. 背景

V8 已完成引擎側埠一對一、form、belt 30／pipe 60、H8 匯流堵塞與 Dev 機器／產品分頁。剩餘問題：

- 產品頁把 materials 經「物品輸出口」假配方混進產品
- 機器外層 ports 與 `modes[]` 重複；多模態時預覽／畫布易讀錯埠
- 拓樸未按機器 width×height 格點定位埠
- 無從產品回推基礎材料的最短鏈路工具
- 引擎仍依賴預選 `recipeIndex`，與「輸入齊全才有產出」語意不符

主題：**強化視覺化預覽工具**（含資料釐清與引擎配方匹配）。

---

## 2. 最終決策

| 決策項 | 結論 |
|--------|------|
| 版本號 | **V9**（不重開 V6；延續 V7／V8 資料與速率） |
| 產品來源 | [`docs/aaaaa/data/products.json`](../../data/products.json)＝已編輯整理的產品全集 |
| 材料來源 | [`docs/aaaaa/data/materials.json`](../../data/materials.json)＝基礎材料（結構異於產品） |
| 產品判定 | 出現在 `products.json` 即為產品（即使另有拆解配方） |
| 假產品 | **停止** codegen `buildSourceProducts`（物品輸出口→源礦等） |
| 基礎材料源機器 | **新建**「基礎材料輸出點」；依品項 `form` 選 belt／pipe |
| 物品輸出口 | 保留；**僅固體**；總產值仍只計回「物品輸入口」 |
| 埠 schema | **全面 modes**；移除外層 `input_ports`／`output_ports` |
| 單形態機器 | `modes: [{ "id": "default", "label": "預設", ... }]`（一元素 list） |
| 預設 mode | `modes[0]`（與現有 `resolveMachineMode` 一致） |
| 引擎配方 | 依實際輸入匹配；不齊＝無產出；屬核心行為變更 |
| 多配方衝突 | 輸入種類集合完全吻合優先；仍多條 → `products.json` 出現順序第一 |
| 最短鏈路 | 從產品回推至基礎材料，**配方步數最少**且無循環（息壤選短鏈） |
| 效率單位 | 個／分：`quantity * 60 / timeSeconds` |
| 速率上限 | belt 30、pipe 60（V8） |
| 演示策略 | **先 F1 盤點**既有案例，再 F2 分項開發 |

### 息壤最短鏈路例（定案說明）

1. 長鏈：砂葉／芽針…→緻密碳…→穩定碳塊＋清水→息壤（多步）  
2. 短鏈：芽針→碳塊；碳塊＋清水（穩定環境）→息壤（少步）  

定案選 **2**。
