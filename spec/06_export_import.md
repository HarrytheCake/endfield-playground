# Feature Spec：藍圖匯入 / 匯出
# CR-06

- **所屬階段：** Phase 2
- **依賴：** CR-01（設備狀態）、CR-02（管線狀態）、CR-03（警示狀態）、CR-04（產能估算）、CR-05（Flow Chart 狀態）
- **文件版本：** v0.3

---

## 1. 功能定位

匯出模組將目前產線的完整狀態序列化為自包含的 `.html` 記錄檔，供使用者分享與瀏覽。匯入模組從記錄檔或 `.json` 還原產線狀態，支援跨版本 migrate 邏輯。

---

## 2. 功能詳細描述

### 2.1 匯出記錄檔（.html）

#### 觸發
工具列「匯出」按鈕 → 輸入藍圖名稱、作者（選填）→ 確認後觸發瀏覽器下載

#### 記錄檔設計原則
- **視覺從簡**：靜態呈現產線狀態，不重新實作拖拉、連線等重度互動
- **資料求完整**：內嵌完整 JSON，可無損匯回模擬器繼續編輯
- **自包含**：所有資源 inline，無外部依賴，離線可瀏覽

#### 記錄檔內容（人類可讀層）

分四個 Tab 呈現：

| Tab | 內容 |
|-----|------|
| 產線佈局 | 靜態格子圖，顯示設備位置、接口、管線走向 |
| 流程 Flow Chart | 靜態 Flow Chart（SVG 渲染），節點與連線關係 |
| 產能估算 | 產出摘要表、電力統計、調度券效率 |
| 警示列舉 | Error 與 Warning 完整清單 |

基本互動（純前端，無需重量框架）：
- Tab 切換
- 設備 / 節點懸停顯示詳細資訊 tooltip
- 警示項目點選時，產線佈局 Tab 高亮對應設備

#### 機器可讀層

人類可讀層之外，記錄檔內嵌完整的藍圖 JSON（含設備擺放、管線、流程圖節點位置、使用者設定等資料），供匯入時無損還原。

---

### 2.2 跨版本 Migrate 邏輯

使用 **Zod** 定義各版本 schema 並實作 migrate。

**設計原則：**
- Migrate 靜默執行，不警示使用者——版本差異屬於系統內部處理，使用者無需感知
- 僅在解析失敗（parse error）時才顯示錯誤訊息，告知使用者檔案損毀或格式不合法
- 每次藍圖 JSON 欄位有變動，須新增一個版本並定義對應的 migrate 規則

---

### 2.3 匯入流程

**支援格式：** `.html`（內嵌藍圖 JSON 的記錄檔）、`.json`（直接為藍圖 JSON）

**流程：**
1. 使用者點選工具列「匯入」按鈕，選擇檔案
2. 系統讀取檔案，偵測格式（HTML or JSON），取得原始藍圖 JSON 資料
3. 進行版本偵測、跨版本 migrate 與格式驗證
4. 若驗證失敗（parse error），顯示錯誤訊息給使用者
5. 成功後顯示確認對話框：「匯入將覆蓋當前畫布，確定繼續？」
6. 確認後，將解析結果還原至產線狀態，觸發流量重算與驗證

---

## 3. 驗證方式

| 驗證項目 | 方法 |
|----------|------|
| 匯出觸發下載 | 點選匯出按鈕，確認瀏覽器下載 `.html` 檔案 |
| 作者選填 | 匯出時不填寫作者，確認仍可正常完成匯出 |
| 記錄檔可瀏覽 | 開啟匯出的 `.html`，確認四個 Tab 內容正確渲染 |
| Tab 切換互動 | 點選各 Tab，確認內容正確切換 |
| 懸停顯示詳細資訊 | 懸停記錄檔中的設備 / 節點，確認顯示對應 tooltip |
| 警示點選高亮聯動 | 點選警示列舉項目，確認自動切換至產線佈局 Tab 並高亮對應設備 |
| 記錄檔僅供瀏覽 | 開啟匯出的 `.html`，確認無法拖拉設備或編輯管線，僅有 Tab 切換與懸停等輕量互動 |
| 機器可讀層存在 | 以文字編輯器開啟 `.html`，確認內嵌完整且合法的藍圖 JSON |
| 匯回還原完整 | 匯出後匯入，確認設備位置、管線、配方、使用者設定完全還原 |
| 跨版本 migrate 靜默執行 | 使用舊版 schema JSON 匯入，確認自動升級成功、無任何警示訊息 |
| 多版本鏈式 migrate | 匯入相隔兩個以上版本的舊版 JSON，確認能依序鏈式升級至最新版本 |
| Parse error 顯示錯誤 | 匯入損毀、格式錯誤或缺少必要欄位的檔案，確認顯示明確錯誤訊息 |
| 匯入覆蓋確認 | 在有現有配置的情況下匯入，確認出現確認對話框 |
| 離線瀏覽 | 斷網情況下開啟匯出的 `.html`，確認正常顯示，無外部資源請求 |
